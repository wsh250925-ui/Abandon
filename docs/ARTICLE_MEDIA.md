# 图文图片维护与验收

更新时间：2026-10-07。

## 403 的实际原因

本次报错文件为 `admin-media/articles/1790045658425-isjscmiartk.jpg`。正文中保存了云存储临时 HTTPS 地址，包含 `sign` 与 `t` 参数；签名失效后服务器返回 403。之前只把 `cloud://` 地址转成新链接，并没有恢复这些旧 HTTPS 地址，因此旧文章仍然失败。不能靠清缓存修复已经过期的签名。

## 修复后链路

1. `utils/article-content.js` 只识别当前项目的云存储域名，将 `admin-media/articles/`、`admin-media/covers/` 的旧 URL 恢复为永久 FileID；其他域名保持原样。
2. 阅读页先拆分正文，文字由 `rich-text` 显示、图片由原生 `<image mode="widthFix">` 显示，保持图文先后顺序和段落样式。
3. 图片由 `wx.cloud.downloadFile` 获取当前本地临时文件；失败时尝试获取新的云临时 HTTPS 地址。不会回退到正文中的旧签名链接。
4. 图片失败后显示点击重试，成功后可点击放大。文件被删除或读取权限未开放时，重试不能恢复缺失文件。
5. 后台恢复旧文章时刷新编辑器预览地址，保存前调用 `EditorContext.getContents` 读取最新正文，并仅重写图片 `src` 为永久 FileID。不修改正文的 HTML 文本实体。

## 数据规则

`articles.content` 仍为 HTML 字符串，字段结构不变。`coverFileId` 和正文上传图片 `src` 应为 `cloud://` FileID。管理员插图时临时预览地址与永久 ID 的映射只存在页面内存中，保存前转存永久 ID。本次修复不改变学习数据、不删除图片、不批量写入线上数据库。

当前域名映射配置在 `utils/article-content.js` 的 `STORAGE` 常量。更换云环境时，必须同时更新该映射；不要把其他云环境的临时 URL 当成当前环境文件。对当前域名的历史图片，读取时可自动恢复，不必重新上传；在后台重新保存一次后，数据库中的正文也会转为永久 ID。

## 部署影响

本次修改仅在 `miniprogram/`，无需重新部署 `learningApi` 或 `aedApi`。重新编译、返回后重新打开文章即可。体验版或正式版用户需更新对应小程序代码版本。存储规则应允许用户读取发布资料，上传权限仍限管理员。

## 自动化验证

执行 `node --test tests/*.test.js`。新增测试覆盖：本次 403 地址、`&amp;` 转义地址、FileID 幂等、外部域名不误转换、编辑器预览映射、正文实体不改变、多图顺序与段落平衡、阅读页使用恢复的 FileID 下载、云接口失败不回退到失效地址。

自动化验证使用模拟云接口；不能证明线上文件是否存在或云存储权限正确。

## 微信与真机验收

1. 打开包含本次报错图片的旧文章，应显示图片，控制台不再请求带旧 `sign` 的地址。
2. 后台新增文章，在第一段与第二段之间插入两张图，保存后打开，文字和图片顺序应一致。
3. 重新编辑同一篇文章，修改标题后保存，已有图片仍能显示；数据库 `src` 为 `cloud://`。
4. 断网打开或触发图片失败，应有可见重试提示；网络恢复后可点击重试。
5. 使用普通学习者账号在 Android、iOS 上各检查一次，验证普通用户有读取权限。
6. 如果永久 FileID 仍报权限错误，在云存储控制台检查原文件是否存在与读取规则，不要把存储写权限开放给所有用户。
